# Research at level 6, part two — dispatch, the evidence rules, agent forms, checks

Read this with `research-6.md`. The rules in section 2 come from the measured literature on research-agent accuracy compiled on 18 Oct 2026 (the report *Accurate research with Claude* in `~/.claude/sessions/stress-test-3-workspace/reports/`): every technique with a measured gain changes what the model sees or how its outputs are selected, not how it is asked to think. None of it was measured on the current Claude family, so each rule is a prior to re-test on the skill's own eval set. Grades: M measured in a study whose primary text was read, on contemporary non-Claude models unless said otherwise; V vendor-reported; G guidance or a tool constraint; I an inference across measured findings.

## 1. Dispatch by tool, stance and model

Each question's **Dispatch** line names the tool as well as the model and, for a top-three question, the stance pairing: `Q4 — data route, Haiku runs the lead's script, price panel 5y; Q1 — paired stance, Sonnet ×2 (long / short), blind; Q7 — missed-question check, Opus`. Haiku takes data pulls with a script the lead wrote or reviewed, extraction from a named source and table-building, never alone on a load-bearing number (no measured extraction error rate exists for small models on tables). Sonnet takes route searches, stance research and the disconfirmation lookups. Opus takes grading, the second read of every threshold-crossing number, inference, the update, the synthesis and the missed-question check. Fable only where the owner's rules already allow it. At level 5 all grading stays on the lead, as `level-5b.md` says; at level 6 non-threshold grading may go to one Opus grader agent, named on the call and blind to the call, while the lead keeps the threshold-crossing findings, the model, the update and the call. Budgets are set in **lookups** (searches, fetches and raw pulls) per question, scaled by the question's rank by value of information; tokens are read from each agent's result afterwards and recorded on the Spend line. The session's web-search cap (about two hundred searches, shared with every subagent, per the Claude Code tools reference of Oct 2026) is allotted in the plan: the lead keeps a running tally from the agents' reported counts and holds about a fifth back for the closing checks; fetches and raw pulls do not count against it. Fan out only for independent, breadth-first questions, with the lead verifying before merging; a dependent chain (a computation that feeds a judgment that feeds the call) stays in one strong model (M, V). Where an agent call takes an effort setting (a Workflow script), research agents run at high effort or above; where it does not, the default stands.

## 2. The evidence rules

- **Framing.** The decision question is rewritten in neutral form before any search; the owner's hypothesis is recorded separately and never appears in an agent brief (I: one-sidedness tracked question framing in the one audit that measured it).
- **Trigger.** Every agent gets today's date and a targeted search trigger: names as written, anything that can change, and the sentence that facts which cannot change need no search; never a blanket "always search" (V: a blanket rule searched on half the prompts that needed none, with no gain).
- **Budget shape.** Short, broad queries first, then narrower; about three to ten lookups for a fact, ten to fifteen per agent for a comparison (G).
- **Lateral reading**, for sources carrying a load-bearing claim only: one fetch of the source's own about page or its encyclopedia entry (a fetch, not a search) before its content is used; the result goes into the source's grade (M for humans; G for agents, whose default is content farms).
- **Fetch prompts.** The fetch tool is lossy by design and the search tool returns titles and links only, so each fetch prompt is a specific extraction question; "the source does not say" is recorded only after a narrower fetch or a raw pull with a shell tool; a JavaScript-rendered page is read through the browser pane's page text, a compressed PDF through a local text extractor; a document that returns an error is pulled from an archive copy before the route is called empty (G, and the verifiers' own experience).
- **Verbatim first.** Every load-bearing number and date is recorded as a verbatim passage with its URL and access date before any summary is written; the grader stores the passage, never a paraphrase (I: the intermediate summary is the dominant error stage in trajectory audits).
- **Tables through code.** Any table or dataset goes through a script, never the prompt (V: 25 of 25 right through code against 7 of 25 pasted).
- **Prose, then structure.** Agents reason in prose and fill the return form at the end; the API's citations feature is not combined with structured output where it is used (G: an API constraint; Claude Code subagents do not use it).
- **Liveness, then support.** `cite_check.py` runs over the brief's sources table before the packet; a dead link is repaired or replaced by its archive copy, and a claim with neither is downgraded to secondary (M: dead links fell from 4.9% to 0.8% on a contemporary non-Claude model). A blocked page (401, 403, 429) is not dead: it is verified by hand or by a raw pull with the owner's user agent. Then one Opus agent that has not seen the brief receives only triples of (sentence, stored passage, link) for the load-bearing citations counted in the Traced line, with any call or recommendation wording stripped, fetches only where a passage is missing, and returns supported, partly or unsupported per triple; what fails is dropped or weakened (M for the design).
- **Sampling with selection.** For a load-bearing fact that is still unresolved and is easy to check once found, several independent retrieval agents by different routes, the answer selected by verification evidence, never by vote. This is the one exception to research.md's rule that no two agents search the same places, and it is limited to the Traced-line claims (M: 49.5% to 70% with a verifier while voting stayed flat).
- **Agreement as a filter.** A citation or number produced independently by several agents is a strong filter (M: 95.6% accurate when more than three independent models produced it), discounted because same-family runs share errors.
- **No self-review, no debate.** The drafting agent is never asked to re-check its own work without new evidence, and same-model debate is never run (I: results are mixed at best, and here it costs searches and anchors the pair); the stance pair stays blind.
- **Stopping.** An explicit evidence-sufficiency check before an agent stops, and a first-class "no answer, here is what was searched" return (M for both failure modes: forcing an answer and over-refusing).
- **Discounts.** A single small unreplicated study is rated low; replication and pre-registration raise certainty (M for the scale of the problem).
- **Separations.** The brief separates information, assumption and judgment, states source quality per source, uses likelihood words with their numeric ranges, and names the indicators that would change the call; these are transparency rules, not accuracy-validated ones, and the brief says so (G).
- **Provenance states.** Every citation the pass emits carries one of three states: *verified passage*, *primary read*, *secondary (primary not read)*. A "could not find" section lists every empty route, every `not searched` and every unreachable document (I: omissions are invisible to the reader, and the figures that failed verification were the ones that had travelled through search summaries).

## 3. What each agent gets and returns

An agent gets only its question, phrased so an answer could be wrong; the flip threshold; the routes to try, the evidence types applicable from the plan, and the lookup budget; the names, dates and setting it needs; the evidence rules above; and, for a stance agent, its stance. Never the provisional call, the ledger, the other questions, or the owner's hypothesis. A disconfirmation agent gets the strategy under test and its mechanism, never which strategy leads. The return form is the agent's output schema where the call allows one: `findings[]` with claim, link or path, publication date, access date, primary or not, the exact passage, the evidence type, `reached via` (connector name, owner file, or web), the provenance state, and the grade inputs as facts (sample size and design as stated, setting and date measured, what the source cites as its origin, venue, pre-registered or not); `routes_tried[]` with the phrasings, places and dates, the empty ones and the `not searched` ones included; `surprises[]` as facts; `searches_used` and `fetches_used`. No grades, conclusions, status lines or implications: agents retrieve, the lead analyzes (owner rule, 5 Oct 2026). A return that carries conclusions is resumed once where the tool allows a follow-up message; otherwise the lead strips the conclusion text, notes the violation, and grades what remains.

## 4. Quality controls on the research itself

- **Source calibration.** Where a source type has a track record (sell-side targets, vendor roadmaps, management guidance, press pre-announcements), that record is a base rate on the source and is applied as part of its grade.
- **Shared origin.** Two sources that cite one origin count as one; the brief shows the citation chain for the top findings.
- **Look-ahead.** Every data and replay route carries the as-of date on each input; a replay uses only inputs dated before its decision date; the pack records the running model's training cutoff beside every forecast, because the model's memory is a second leak that date filters do not close. A point-in-time run is sealed: the lead reads a T-dated input pack built before it reads anything else (the decision; the rules in force at T from the version history, or the owner's chosen rules stripped of post-T dates and account facts; the packet, the bundle, the filings) and no project readme, plan or policy file; truth and the full price panel sit outside the session's reach until scoring; a manifest with the hashes of the pack, the priors and the skill files is committed before research; horizons are counted in trading days on the exchange calendar (the first run's harness counted calendar days, so "+63d" was 44 trading days); web search is off; and every attempt on a date is kept and scored, none dropped.
- **Judging.** When a model judges research output, one call with a numeric score and pass or fail on accuracy, citation support, completeness, source quality and efficiency; answer order swapped; a model that did not write the draft; a human spot-check (V, with position and self-preference biases measured on older models).
- **The eval set.** The harness answer keys in `~/.claude/sessions/stress-test-3-workspace/answer-keys/` (eight decisions today, to grow to about twenty) are re-run when a rule changes, so each rule above gets an effect size measured on this skill rather than borrowed.
- **Closing checks.** The missed-question agent's second pass (level 6) and the research pre-mortem close the research, and both go in the brief.

## 5. Commands

Run from any folder with the skill's absolute path.

```
py -3 ~/.claude/skills/stress-test-3/scripts/cite_check.py <brief.md> --ua "<name> <email>"   # liveness of every URL; archive lookup for dead ones
py -3 ~/.claude/skills/stress-test-3/scripts/cite_check.py <brief.md> --out CITES.md          # table to a file; exit 1 if any URL is dead with no live archive, or if no URL was found
py -3 ~/.claude/skills/stress-test-3/scripts/cite_check.py --selftest                         # offline smoke test
```

The user agent matters: some filing databases refuse requests without a name and contact, and the owner supplies them. A result of `blocked` is a page to check by hand, not a dead link.
